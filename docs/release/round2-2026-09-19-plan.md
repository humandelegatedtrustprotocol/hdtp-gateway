## R2 · An export is chats and contacts, and nothing else — `DONE`
Today the node's `backup create` is a snapshot of the whole database (every table; leaf keys
stripped since F1) with the blobs and, by default, `keyring.key`. The cloud's identity archive is 22
tables — owners, credentials, sessions, tokens, audit, invites, integrations (with the upstream
secret REVEALED), settings, the relay tables — sealed to the owner.
The rule: an export carries **the identity's name** (slug, display name, the root's fingerprint and
certificate — public, and what the data belongs to), **contacts**, and **chats** (threads, messages,
and the media they reference). No key of any kind, no settings, no credentials, no sessions or
tokens, no audit chain, no invites, no leaf ledger. Every import ends at an account that is named
and not served until its wallet issues THIS host a new leaf.
- **R2a · node.** A logical export written THROUGH the `Store` interface — so it is an allow-list by
  construction, works on Postgres as well as SQLite (a Postgres node has never had an export), and
  needs no hand-written SQL. One JSON manifest line and JSON Lines rows, in a tar with the media.
  `pact-gateway export` / `import` replace `backup create` / `restore`: it is not a backup of the
  node any more and must not be called one. **Goes:** the database snapshot, `SQLite.Snapshot`
  (E2's single counted exception — the count becomes zero), `StripKeys` and its queries,
  `-same-node`, `-data-only`, `-without-master-key`, the keyring-id manifest, and their tests.
  The lost-master-key recovery of F1b becomes: `export`, a fresh data directory, `import`, a leaf.
- **R2b · cloud.** The owner's export builds from the same allow-list; nothing is revealed, so the
  `reveal` ports, `KEY_MATERIAL_INCLUDED_NOTE` and the keys-included branch go. The platform's own
  weekly snapshot is NOT an export — it never leaves the platform — and keeps its full table list.
  `npm run leave` stops fabricating a SQLite store with goose bookkeeping ("29 versions through
  29") and writes the node's import file instead: the coupling E3/B2c kept tripping over is gone.
  `import20.ts` takes the same allow-list.
  *To establish, not assume:* the workspace document in `index.pact` is what `docs/privacy/dsar.md`
  says serves GDPR access and portability. That is a legal duty, not a product choice; it is left as

- **R2c · protocol and docs.** §9 lists "contacts, messages, media, invites, settings"; it says what
  travels now. Node SPEC §3.10/§11/§12, README, operations, the cloud's export doc and terms.
*Verify:* a test that reads an export's BYTES and finds no table but the four, no key, no setting,

**Design, settled before any code (2026-09-19):**
- *Object migration `1004_drop_1x`, forward-only, one transaction per migration.* The runner was
  not transactional: a statement failing half-way left a version unrecorded and statements that
  cannot be re-run (`DROP COLUMN` of a column already gone), which bricks an object at start.
  Each migration now runs inside the object's `transactionSync`.
  Drops `accounts.protocol, accept_1x, prev_fingerprint, prev_key_sealed, grace_until` and
  `contacts.protocol`; deletes fan-out rows that are not a move's, drops `kind`, renames the table
  `move_fanout` and `new_fpr` → `leaf_kid` as the node did in 0036; drops `relay_allowlist` and
  `relay_queue`.
- *A key-pinned contact row is NOT deleted.* Its threads and messages hang off it, and deleting a
  person's data in a production object is not this migration's call. It has no leaf, and it is
  refused by what it lacks — "no certificate is held for this contact" — not by a generation
  number. `accounts.prev_key_sealed` could hold a sealed private key from a rotation in flight;
  dropping the column destroys it, which is what 1.x's own rule asked for.
- *`protocol` leaves the API as well as the schema.* On an identity it had come to mean "has the
  wallet issued a leaf yet" (1 = no, 2 = yes), a live 2.x state under a retired generation's
  number — the node's `Certified`. `/v1` answers `certified: boolean`; a certificate, an install
  and an import stop answering `protocol: 2`; a contact stops carrying it. The portal follows.
- *D1:* `identities.protocol = 2` meant "`fingerprint` is the ROOT's". The column goes; a row
  that was not 2 has its `fingerprint` set NULL first (it held a host key's, which is nobody),
  provisioning stops writing one, and `certified` is "`fingerprint` is not null".
- *Archives.* The manifest's `protocol` goes; "a 1.x export" becomes "an archive that names no
  root". A snapshot taken BEFORE this migration lists tables that no longer exist; a restore used
  to refuse any table the object lacks. It skips the three retired ones and says so in its report.
  `nodeTables()` applies the cloud migrations' DROP and RENAME, so exports and the leave file stop
  naming tables that are gone.

**Done, 2026-09-19.** Everything in the design above is built. What it touched, beyond the plan:

- *Object migration `1004_drop_1x`* and *D1 `0015_drop_1x`* (generated: the D1 manifest could
  only ADD a column; it has `removedIn`/`removedAfter` now, 0001–0014 still generate byte for
  byte, and `liveColumns` is what the data layer and the records of processing read).
- *The runner is transactional* — each migration and the row that records it land together.

## R8 · The known gaps, with standard tooling — `DONE`
Research first (web), choice recorded here with sources, then built.

**What the research said, and what was chosen.**
- *Partitions.* Jepsen injects one with `iptables … -j DROP` and heals by resetting the chains;
  Pumba wraps `tc netem` for containers; Toxiproxy is the standard TCP proxy for faults inside a
  test process, and its `timeout` toxic passes the connection and then lets no data through. The
  distinction that matters is DROP versus disconnect: a dropped packet leaves a caller WAITING,
  which is what a dead link does; `docker network disconnect` fails at once, which is a different
  fault and an easier one. So: the container harness keeps `tc netem loss 100%` (it already had
  it), and the in-process tier uses Toxiproxy. Sources: jepsen-io.github.io/jepsen/jepsen.net.html,
  aphyr.com/posts/281, github.com/alexei-led/pumba, github.com/Shopify/toxiproxy.
- *Reproducible wasm.* `--remap-path-prefix` and a pinned toolchain are necessary and not enough:
  rust-lang/rust#117597 reports wasm32 output differing between macOS and Linux under cargo with
  one rustc, and projects that need identical bytes pin the BUILD PLATFORM in a container and have
  CI rebuild and compare hashes. Cargo's `trim-paths` was stabilised in rust-lang/cargo#17488 and
  is not in the pinned 1.92.0. Sources: github.com/rust-lang/rust/issues/117597,
  github.com/rust-lang/cargo/pull/17488, docs.internetcomputer.org (reproducible builds).

## G: the pact-identity code review, and the twelve defects it found (2026-09-20)

Five reviewers read `pact-identity` in slices — certificates and encoding, envelopes/HPKE/vault/the
API boundary, the CLI and wallet, the Go port, and the JS harness with the pin tooling and hooks.
Every finding below was verified against the source before it was acted on, and every fix has a guard
that is red on the code as it was.

### G1 — the three blockers in the pinned core. `DONE` (umbrella `b973522`, pinned `b88568b`)
- **Six bytes of DER panicked the boundary.** `der.rs` compared `at + len > buf.len()`, and `len` is
  built from up to four length octets — so on wasm32, where `usize` is 32 bits, `30 84 FF FF FF FF`
  wrapped the sum, passed the guard, and panicked on the slice. **Measured in the pinned build:**
  `RuntimeError: unreachable`, which is the boundary throwing across — the one thing CONTRACT §0 says
  it never does. One correction to the reports: the module still answered afterwards, so "poisons the
  instance for the life of the page" is not what I saw in Node. Found independently by two reviewers.
  Reachable from every DER entry and, with no caller cooperation, from `decide` through an attacker's
  envelope chain. 64-bit hosts compute the same guard correctly, which is why `cargo test`, the CLI and
  the Go node never saw it. The intrusion suite and the seed gained the vector: against the old pinned
  wasm it reported `threw: unreachable`, and it blocks now.
- **An `i64` wrap bypassed the skew window AND the 30-day cap.** `(now - ts).abs()` with
  `ts = i64::MIN + now` overflows to `i64::MIN`, and `i64::MIN.abs()` is `i64::MIN` again in release —
  `<= 300`, so the window passed; `exp - ts` wrapped the same way. Two normative MUSTs, from a
  stranger, in the shipped build: the release profile sets no `overflow-checks`, so a debug build
  panicked where the pinned one accepted. A ~34,000-year band is checked before any arithmetic;
  which of the two refusals a caller gets is deliberately unchanged. The other ports compute in
  `float64` and already refused — so Rust alone wrapped, and a parity case with the extreme `ts` is
  the durable guard.
- **Argon2id parameters were unbounded when OPENING a vault** — read from the document before the
  passphrase is tested, so forging them is free: 256 GiB asked, or four billion passes that never
  return. (It ran away in my own harness when I first added the case, which is the finding
  reproducing itself.) Sealing had no floor either, ignored `name`, and truncated with `as`, so
  `m_kib: 2^32 + 8` became 8 — the weakest legal KDF, silently. One bounded parser serves both paths
  with the same four numbers in both ports.

Also in that commit: `HeldKey` derived `Debug` over a leaf private key in a file where `PrivateKey`
deliberately does not; `generate` fell back to an all-zero seed if randomness came back short; the
derived ROOT seed dropped un-zeroized, which CONTRACT §6's list reads as covering; and
`the_boundary_never_throws` asserted six ordinary error returns on the one target that HAS a
`catch_unwind` backstop, while wasm32 compiles none and `panic = "abort"` makes unwinding impossible —
renamed, with a test that feeds it the three inputs that panicked or ran away.

### G2 — the Go port refused less than the Rust core. `DONE` (umbrella `5277085`, `436dac3`)
- **A remote panic from six bytes.** `nameOf` indexed `parts[0]` one line above the `len(parts) < 2`
  that would have made it safe, so an empty attribute in a subject or issuer Name panicked the parser —
  reached through `Decide` → `ValidateChain` → `Parse` before any signature is verified, and through
  card intake. Two `csr.go` sites repeated it. **Proven:** the new case panics with `index out of range
  [0] with length 0` on the code as it was.
- **An X25519-keyed leaf passed the profile check**, because `AlgorithmOf` errors only on an EMPTY
  `Alg` and `ParseSPKI` names X25519 — so the node would have pinned a chain the wallet and the cloud
  both refuse, leaving the peer stuck rather than cleanly rejected. It names the admitted set now.
- **`IPIsPrivate` admitted `255.255.255.255`**: `netip` has no `IsBroadcast` and 255 is not multicast,
  where Rust's `v4_private` calls `is_broadcast`. `manager.go` vets a stranger's card endpoint with
  this, so a guest could be pinned at the IPv4 broadcast address by the node and refused by the wallet.
- Plus two `why` divergences the new KDF cases surfaced, both now Rust's wording.

### G3 — why a dozen divergences survived: parity's gate counted refusals as successes. `DONE`
`provenWhole` tested for a **top-level** `error`, which `decide` (`{result:{code}}`) and
`validate_chain` (`{ok:false}`) never set — so both were recorded as "compared whole on an answer that
succeeded" while every one of their cases was a refusal. **`validate_chain` — the six chain rules — had
never had a successful answer compared between the ports at all**: fourteen cases, all refusals, and no
plain valid-chain case. Corrected, the gate went red and named both; the success cases are added, and
the first immediately caught what a reviewer had predicted by reading — `decide`'s `tool` member, `null`
in Rust and **absent** in Go. 288/288 agree now, 38 of 38 compared whole.

### G4 — the tooling written on 2026-09-20 said more than it did. `DONE` (umbrella `05f7600`)
Nine defects in my own work, none of which a gate could see:
- `live.mjs` **crashed on an ordinary answer**: a JSON-RPC `error.code` is a NUMBER and `post()` calls
  `.startsWith` on it, so against any receiver answering a plain JSON-RPC error the battery died as an
  unhandled rejection and lost every result collected. The Rust driver had read that shape since
  2026-09-18.
- **`--allow-insecure` unauthenticated the card.** It turned off certificate verification and then
  fetched the card over that same channel, so a carrier could hand over its own card, hold the key all
  28 envelopes were sealed to, and the tool printed "28 blocked, 0 reproduce" and exited 0 — a
  fabricated clean security report. It requires `--card` now, which is the whole of its safety argument.
- **The pin covered 2 of 12 shipped files.** The Worker imports `pact_identity_wasm.js`, 13 KB of glue
  that marshals every argument and answer across the boundary; it was vendored beside the module and
  hashed by nothing, so editing it passed every check. All twelve are recorded, the cloud's
  `check-wasm.mjs` holds every vendored file to them, and the two packages' glue turns out NOT to be
  identical — so verifying a copy against "the web package's entry" was a live hazard too.
- **"ok pin-of-commit" could be true of bytes a different builder made**: the image digest, platform and
  wasm-pack release were not inputs and nothing compared them. They are `js/builder.json` now, on the
  input list and compared by `verify.mjs`.
- **Three tests and two scenarios could not fail.** "The attacker is new every run" compared signatures
  over a fresh HPKE ephemeral, so it passed with the fixed seed it was written to catch — **the mutation
  check I owed it and did not do**; it asserts on her root now and fails on that seed. One assertion

- The two drivers were held to each other by name and order but **not by expected code**. Now held.
- `vectors check` had no floor: a section deleted from Appendix B printed a smaller `N/N` and exited 0.
- The **pre-commit hook silently reformatted unstaged sibling modules** (`rustfmt <path>` recurses;
  `skip_children` is unstable), so staging `lib.rs` rewrote 13 siblings unreported — and the next
  `--pin` then refused, naming files nobody had touched. It formats through stdin now. Proven both ways
  in a scratch clone.
- `musts.mjs` accepted any Rust `fn` as a holder (352 names where 70 are tests) and excused an unknown
  repository prefix for ever.

### G6 — the one item parked for a decision. `OWNER`
**ECDSA signature malleability.** For an identity whose root is P-256 (§2 permits it), anyone can take
a leaf's signature, compute `s' = n − s`, and hold a certificate that verifies under the root with the
same fingerprint, endpoint and `notBefore` but different bytes. §14.3 then reads "different bytes, same
notBefore" as `conflict`, so a card poisoned in transit pins a leaf that can never talk — and it is
invisible to the one check §3 asks a person to make. Denial of service, not impersonation; Ed25519
unaffected. Either a §14.1 low-S profile rule (one line in each of three ports plus a SPEC sentence,
keeping verification semantics identical to the seed so parity survives) or a written §14.5 residual
row. It touches `keys.rs`, so it wants to ride the next commit that re-pins for a reason of its own.

### G7 — recorded, not fixed
Two cross-port divergences that need a joint decision rather than a unilateral change, because
tightening one port would diverge from the seed, which CONTRACT §0 makes the authority: an
out-of-range DER time (`20260230120000Z`) that Rust normalises the way the seed does and Go refuses;
and an OID subidentifier over 128 bits that Rust wraps in `u128` where Go and the seed use big
integers. Also: an extension value's own tag is unchecked in both ports, and `basicConstraints`
tolerates extra elements — port-consistent, so spec divergence rather than a split.
