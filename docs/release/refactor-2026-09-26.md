## 1. Phase T — the framework (first, because the refactor must be held by tests)

The same five ideas in each repo, each in its own language:

1. **A scenario is data**: a registry entry with a stable `id`, `name`, `tier`, `needs` (docker,
   chrome, kernel, cf, private-sibling, staging), `requires`/`provides` (what an earlier scenario
   leaves), budgets it spends, and a `run`. Order is computed from `requires`, not array position.
2. **A step is soft**: `step(label, fn)` records evidence and a verdict (PASS, FAIL, UNREACHED,
   SKIPPED + reason), and a scenario keeps going to its end; UNREACHED stops only the scenarios that
   `require` what it would have provided.
3. **One result schema** for every runner: `{ run, repo, tier, cases: [{ id, verdict, reason,
   evidence, ms }] }` written as JSON beside the console table. A tier that promised a case and got
   SKIPPED fails. Runs of record become these files.
4. **Shared fixtures, built once**: one browser/authenticator/download/wait package per repo (not
   three copies), one cast (Alina, Bharat, Mallory, a fixed clock) built by the seed, one node
   builder with port and prefix allocation.
5. **Guards hold tables to the PRODUCT, never the driver's text**: one `hold()`/`drift()` helper;
   the ~90 `toContain`-on-driver-source assertions are replaced by registry checks (ids unique,
   `requires` satisfied, budgets computed from metadata, every UI word held to its source).

### T1 · pact-cloud `gateway/e2e/`
- New `gateway/e2e/lib/`: `verdict` (Finding/Unreached/step, from staging-pair), `browser`
  (chromePath, launch, virtual authenticator, downloads by name+mtime, bringToFront — today in
  ceremony-smoke AND staging-identity), `wait` (named budgets replacing ~42 literal timeouts),
  `teardown` (scoped per scenario and fixture), `report` (JSON + table), `registry`.
- Scenarios move to `gateway/e2e/scenarios/<group>/*.mjs`, one `defineScenario({...})` each; the
  hook-woven sub-scenarios (inS2Pending, s36After, r4Before/After, …) become scenarios with
  `requires`. `kit.state` and the module-level `kept` become a typed context
  (`ctx.provide('thread', …)`, `ctx.need('thread')`). Pass two becomes a phase parameter, not an id
  suffix.
- `staging-pair.mjs` shrinks to the CLI: `--only`, `--from`, `--list`, `--pass`.
- `ceremony-smoke.mjs` and `staging-identity.mjs` use the same `lib/`.
- `staging-calls*.mjs` keep their data; the hand-written `.d.mts` twins are replaced by JSDoc types
  checked by `tsc` (one source per table), and `domains` joins `FRAGMENTS`.
- Budgets (`GUEST_CALLS`, `CONTACT_CALLS`, `PASS_TWO`, promo capacity) computed from scenario
  metadata and checked, not maintained by hand.
- `gateway/e2e/TESTING.md`: how to add a scenario (target: 2 files — the scenario and, if it needs
  one, its table entry).
- Migration held by behaviour: the full pair before (run 44) and after each group moves must PASS
  the same id set.

### T2 · pact-gateway `harness/`
- `scenario.Register(Spec{ID, Tier, Needs, Timeout})` beside each test; the Makefile tiers select
  by tag, not by test-name regex; harness-design.md's S/T table generated from the registry (and S1,
  S3, S5 either written or removed from the doc).
- One node builder (fold `SetupPaired`, `StartOwnedNode` and pairing_live_test's third copy and the
  six duplicate helper pairs), with a port/prefix allocator (fixes the collisions).
- Images pinned by digest; readiness probes instead of `time.Sleep`; the `nodeImage` constant once.
- A promised-but-skipped scenario fails its tier; `-json` reports per scenario.
- The invariants either observe something or are removed (rule 9).

### T3 · pact-identity `js/` and `crates/pact`
- Parity cases get stable ids; `expected` keyed by id, and an unknown key fails. Case files split
  by contract section (the 923-line parity.mjs becomes a runner plus `cases/<section>.mjs`).
- One cast module built from the seed, used by parity, intrude, live, live.test.
- The live battery's scenario list as data (JSON) consumed by live.mjs AND `pact vectors intrude`
  (via `include_str!`; the CLI crate is not a pin input), replacing the regex over Rust source.
- A persistent Go adapter process (one spawn per suite, not per call); `record.mjs --check` reuses
  the parity run instead of repeating it; one Appendix B slicer.
- The dispatcher surfaces read from the contract, not by indentation-sensitive regex.

### T4 · across repos
- One result schema (above) in `pact-gateway/docs/testing.md`, which also says which tier runs
  where (pre-commit, pre-push, local live, staging) and what each costs.

## 2. Phase S — the refactor (after T, each held by the suites T made honest)

### S1 · mechanical, no behaviour change (existing tests unchanged and green)
Cloud:
- Break the import cycles: `api/v1/errors.ts` (ApiRefusal, denialMessage), `mcp/owner/errors.ts`
  (McpError), `orgEvent` out of `table.ts`; oauth register⇄cimd and token⇄grants.
- One `appendOrgEvent` for the nine byte-identical `org_events` writers.
- Split `api/v1/table.ts` (3822) by resource, concatenated in today's order (Hono matching and
  OpenAPI order depend on it) plus `shapes.ts` and `refusals.ts`.
- Split `portal/routes.ts` (1496) into registrars, the `/auth/test-*` routes in their own file.
- Identity DO (3911): integrations and archive/snapshot sections into modules, the class keeping
  one-line delegates (stub.ts and check-unwired read method names).
- Test fixtures consolidated (`seedWorkspace`, `sessionCookie`, `wallet` — copied in 49/22/10 files).
- Portal wire types in one `types.ts` (Contact is defined three times).
Node and identity:
- Split `cli.go` (serveWith is 662 lines) into per-subcommand files; `conformance.Run` (1401 lines)
  per area; `Mount*Pages`/`NewServerWithExtra` into named handlers with one `accountParam(r)`.
- `go/api.go`'s 885-line closure map split per contract section; `wallet.rs` into
  `wallet/{files,card,id,contacts}.rs`; `vectors.rs`'s intrude/check into modules (not pin inputs).
- An import-layering guard in `integrationtest` so the layers cannot regress.

### S2 · structural, low behaviour risk
- Node: services out of `cli` (settings, audit sink, owner presence, retention) into packages;
  break node→internalui (inject the landing handler); a calendar port in `public` so providers
  depend on it; `store.Store` (128 methods) split into role interfaces embedded in `Store`, consumers
  narrowed.

### S3 · behaviour-touching (each its own item, with rule 3 refusals and rule 7 audit tests)
- The 26 owner-MCP node-served actions through the `/v1` pipeline (invite bounds and host, the
  25 s vs 50 s wait, two validators, two audit call sites). **Design decision (owner)**: the split
  was deliberate for Go-node parity.
- One bearer resolver and one session-admission function for `/v1`, `/mcp` and the portal.
- Portal-only `/api/*` routes: move to `/v1`, or name them in a divergence list a test holds; drop
  the two that only tests call (`/api/workspaces/:id/identities`, `…/entitlements`); `invalid_body`
  → `bad_request`.
- `isWorkspaceAdmin` / `teamGate` decisions into gate actions (rule 4).
- One workspace-state transition service for `/v1` and admin.
- The node uses the port's primitives (envelope type, fingerprint, key generation, base64url).
- The `…20` generation suffixes renamed away (migration names stay; append-only).
- SQLite/Postgres adapter duplication behind shared helpers over the sqlc queriers (highest risk;
  engine conformance + `make sqlc-check`).

### S4 · the identity core crate, last and once
`api.rs` dispatch and `envelope.rs` `decide` split into modules — one commit, one re-pin, one
re-vendor, one ceremony pin, one staging run (any line move changes the pinned bytes).

### Deferred (named, not done here)
- `ceremony.js` to TypeScript (build- and pin-touching for any edit).
- The admin console's Cedar shadow → enforce cutover (a policy decision).

## 3. Order and cost

T1 → T2 → T3/T4 → S1 → S2 → S3 (item by item) → S4. Each phase ends with the full gates in all
repos and, where the cloud changed, a staging pair run filed as a run of record. Branches and PRs
per repo; pact-cloud and pact-protocol pushed before the umbrella pointer moves.
