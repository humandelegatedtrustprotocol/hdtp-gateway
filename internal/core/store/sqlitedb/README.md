# internal/core/store/sqlitedb

The SQL the SQLite store runs, generated by sqlc as Go. It is rank 0 in the layer table
(`internal/integrationtest/layering_test.go`): it imports no package of the node. The only package that
imports it is `internal/core/store`, whose `SQLite` type calls these methods on `*sqlitedb.Queries` and
maps the rows to the store's domain types; `store` also converts the Postgres rows to this package's types
(`sqlitedb.Contact(r)` and the like), so that a row is mapped once for both engines. Nothing else in the
node may name a connection or a statement (standing rule 1).

**Do not edit it.** Every `.go` file here except `doc.go` carries `// Code generated by sqlc. DO NOT EDIT.`
and is the output of `make sqlc`. To change a statement, edit `queries/sqlite/*.sql`; to change the schema,
edit `migrations/sqlite/`; then run `make sqlc` and commit the result.

## What it holds

Generation is configured by the first entry of `sqlc.yaml`: engine `sqlite`, schema `migrations/sqlite`,
queries `queries/sqlite`, package `sqlitedb`, output here, with the table `leaves` renamed from sqlc's
`Leafe` to `Leaf`. The generator is pinned in the `Makefile` (`SQLC := go run
github.com/sqlc-dev/sqlc/cmd/sqlc@v1.30.0`) and nowhere else.

| Generated file | From | Holds |
|---|---|---|
| `db.go` | | `DBTX` (the part of `*sql.DB` and `*sql.Tx` the queries use), `New`, `Queries`, `WithTx` |
| `models.go` | `migrations/sqlite` | one struct per table: `Account`, `AuditEvent`, `Contact`, `Leaf`, `Message`, and so on |
| `core.sql.go` | `queries/sqlite/core.sql` | owners, accounts, memberships, credentials, sessions, tokens, settings, move fan-out, the audit trail and its anchor, leave deletes |
| `contacts.sql.go` | `queries/sqlite/contacts.sql` | contacts and pins |
| `identity_state.sql.go` | `queries/sqlite/identity_state.sql` | the root and leaf ledger, tombstones, former endpoints, pending addresses, the wallet request state |
| `invites.sql.go` | `queries/sqlite/invites.sql` | invites |
| `integrations.sql.go` | `queries/sqlite/integrations.sql` | integrations, catalogs, exposures, idempotency records, pending requests |
| `messaging.sql.go` | `queries/sqlite/messaging.sql` | threads, messages, blobs, read markers, retention deletes, imports |
| `changes.sql.go` | `queries/sqlite/changes.sql` | the change log |
| `leases.sql.go` | `queries/sqlite/leases.sql` | leases |
| `presence.sql.go` | `queries/sqlite/presence.sql` | owner presence |

Each query is one method on `*Queries`, named by its `-- name:` line, with a `Params` struct when it takes
more than one argument and a row type (a `models.go` struct, or a result struct for a partial `SELECT`).
`doc.go` is the one hand-written file. It holds only the package comment, which a generated file cannot
carry.

## What it refuses, and how

It refuses nothing itself. A method returns the driver's error, and `sql.ErrNoRows` from a `:one` query
with no row; `internal/core/store` turns the second into `store.ErrNotFound`, which is the same value.
The schema's constraints (unique, foreign key, `CHECK`) and the audit trail's triggers refuse in the
engine, and surface here as the driver's error.

## Invariants

- **The committed code is what the sources produce.** `make sqlc-check` regenerates into a scratch copy and
  fails if either generated directory differs; the pre-push hook runs it. It is not part of `make check`,
  because it builds sqlc from source.
- **Every query in `queries/sqlite` has a method here and every method has a query**
  (`TestQueriesMatchTheHandWrittenCode`, `internal/integrationtest/queriesdrift_test.go`), checked on every
  `make check`. `WithTx` is the one method that is not a query.
- **Query sources are ASCII** (`store.TestQuerySourcesAreASCII`): sqlc v1.30.0 slices statements out of the
  file by a rune offset while reading bytes, so one non-ASCII character in a comment corrupts every
  statement after it.
- **Every statement has a plan** that does not scan a growing table without a listed reason
  (`store.TestEveryQueryHasAPlan`, which reads the statements from this package).
- **A statement that writes a contact's `leaf` writes `leaf_fingerprint` with it**
  (`store.TestEveryStatementThatWritesALeafWritesItsFingerprint`).
- **Nothing outside `internal/core/store` imports it** (`TestImportsPointDownTheLayers` and
  `TestNoHandWrittenSQLOutsideTheStore`).

## Held by

`internal/integrationtest`: `queriesdrift_test.go`, `nohandsql_test.go`, `layering_test.go`.
`internal/core/store`: `sqlc_test.go`, `queryplans_test.go`, `leaffingerprint_test.go`, and the whole
conformance suite, which exercises these statements through the `SQLite` store.

## What it does not do

- It does not map rows to domain types, apply defaults, or encode permissions as JSON: `store/params.go`
  and `store/rows.go` do.
- It does not open a database, migrate it or manage transactions: `store.OpenSQLite`, `Migrate` and
  `Atomically` do, and hand it a `*sql.Tx` through `WithTx`.
- It does not contain the Postgres statements. `pgdb` holds those, and it has five that this package has
  not: `ListenChanges`, `LockAccountRow`, `LockAuditChain`, `LockChanges` and `NotifyChanges`, which exist
  because SQLite takes the write lock at BEGIN and has nothing to listen on.
